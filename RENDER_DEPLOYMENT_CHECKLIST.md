# 🚀 Render Deployment Checklist for ManagePetro

## Overview
This checklist ensures your Render deployment with Supabase PostgreSQL database is properly configured for automatic seeding.

## ✅ Pre-Deployment Checklist

### 1. Repository Setup
- [ ] `render.yaml` exists in **repository root** (not in backend/)
- [ ] `render.yaml` has `rootDir: ./backend` setting
- [ ] `render.yaml` has `preDeployCommand: python init_production_db.py`
- [ ] `backend/init_production_db.py` exists and is executable
- [ ] `backend/db/schema.sql` exists
- [ ] `backend/db/seed.sql` exists
- [ ] `backend/requirements.txt` includes `asyncpg`

### 2. Supabase Database Setup
- [ ] Supabase project created
- [ ] PostgreSQL database is running
- [ ] Got connection string from: Supabase Dashboard → Project Settings → Database → Connection String
- [ ] Choose **Session Mode** pooler (recommended): `postgresql://...@aws-0-[region].pooler.supabase.com:5432/postgres`
- [ ] Alternative: Direct connection (IPv6 required): `postgresql://...@db.[project-ref].supabase.co:5432/postgres`

### 3. Render Service Setup
- [ ] Deploy using **"New → Blueprint"** (not "New → Web Service")
- [ ] Connected to your GitHub repository
- [ ] Render detects `render.yaml` in root

### 4. Environment Variables in Render
Go to: Render Dashboard → Your Service → Environment

Required variables:
- [ ] `DATABASE_URL` = Your Supabase connection string
- [ ] `WEATHER_API_KEY` = From weatherapi.com
- [ ] `TOMTOM_API_KEY` = From developer.tomtom.com
- [ ] `GEMINI_API_KEY` = From makersuite.google.com
- [ ] `JWT_SECRET_KEY` = Auto-generated by Render or create your own
- [ ] `FRONTEND_URL` = Your frontend URL (e.g., Vercel URL)

Optional variables:
- [ ] `JWT_ALGORITHM` = HS256 (default)
- [ ] `JWT_ACCESS_TOKEN_EXPIRE_MINUTES` = 30 (default)
- [ ] `DEFAULT_LLM_MODEL` = gemini-2.5-flash (default)

## 🚀 Deployment Steps

### Step 1: Push Changes to GitHub
```bash
git add .
git commit -m "Fix Render deployment configuration"
git push origin main
```

### Step 2: Deploy to Render
If using blueprint:
1. Go to Render Dashboard
2. Click "New" → "Blueprint"
3. Connect your repository
4. Render will read `render.yaml` from root
5. Click "Apply" to create the service

If already deployed:
1. Trigger manual deploy or push to trigger auto-deploy
2. Wait for deployment to complete

### Step 3: Check Logs
1. Go to Render Dashboard → Your Backend Service
2. Click "Logs" tab
3. Look for **"Pre-Deploy"** section (not regular logs)
4. You should see:

```
🚀 MANAGEPETRO DATABASE INITIALIZATION - STARTING
================================================================================
✅ Database connection successful!
📊 Tables found in database: X
```

### Step 4: Verify Seeding
Look for these messages in Pre-Deploy logs:

**Schema Creation (first deployment only):**
```
🏗️  CREATING DATABASE SCHEMA
================================================================================
✅ Schema creation completed: X successful, Y skipped, Z failed
```

**Data Seeding (first deployment only):**
```
🌱 SEEDING DATABASE WITH INITIAL DATA
================================================================================
✅ Database seeding completed: X successful, Y skipped, Z failed
✅ Data verification successful - database properly seeded
```

**Final Success Message:**
```
✅ DATABASE INITIALIZATION COMPLETE (took X.XXs)
================================================================================
```

## 🐛 Troubleshooting

### Issue: "No logs about database initialization"
**Cause:** `render.yaml` not in repository root or not using blueprint deployment

**Solution:**
1. Verify `render.yaml` is in repository root: `ls -la render.yaml`
2. Delete the service in Render
3. Redeploy using "New → Blueprint" method
4. Render should show "Detected render.yaml" during setup

### Issue: "❌ DATABASE_URL environment variable is not set"
**Cause:** Missing DATABASE_URL in Render environment variables

**Solution:**
1. Go to Render Dashboard → Service → Environment
2. Add variable: `DATABASE_URL` = Your Supabase connection string
3. Save and trigger redeploy

### Issue: "❌ Database connection failed"
**Cause:** Invalid connection string or database not accessible

**Solution:**
1. Verify connection string is correct (copy fresh from Supabase)
2. Try Session Mode pooler: `postgresql://...@aws-0-region.pooler.supabase.com:5432/postgres`
3. Ensure no extra spaces or quotes in DATABASE_URL
4. Check Supabase dashboard that database is running

### Issue: "Schema created but no data"
**Cause:** seed.sql had errors during execution

**Solution:**
1. Check Pre-Deploy logs for specific SQL errors
2. Common issue: TRUNCATE failing on empty tables (safe to ignore)
3. Verify seed.sql is PostgreSQL-compatible (not MySQL)
4. Check the verification message after seeding

### Issue: "Tables already exist. Skipping schema.sql" but no data
**Cause:** Previous deployment created tables but seeding failed

**Solution:**
1. In Render Shell: `cd /opt/render/project/src && python init_production_db.py`
2. Or connect to database directly and run: `psql $DATABASE_URL -f backend/db/seed.sql`
3. Check logs for why seeding failed originally

## ✅ Success Indicators

You'll know everything worked when:

1. ✅ Pre-Deploy logs show initialization starting
2. ✅ Database connection succeeds
3. ✅ Schema created or detected
4. ✅ Data seeded or detected
5. ✅ "DATABASE INITIALIZATION COMPLETE" message appears
6. ✅ Server starts successfully after initialization
7. ✅ You can access the API docs at: `https://your-backend.onrender.com/docs`

## 📝 Post-Deployment Verification

Test your backend:
1. Open: `https://your-backend.onrender.com/docs`
2. Should see FastAPI documentation
3. Try endpoint: `/api/health` should return `{"status": "ok"}`

Test database seeding:
1. Use an API endpoint to fetch data (e.g., `/api/stations`)
2. Should return demo data from seed.sql
3. Or check in Render Shell: `psql $DATABASE_URL -c "SELECT COUNT(*) FROM users;"`

## 🔄 Re-seeding

If you need to re-seed the database:

**Method 1: Render Shell**
```bash
cd /opt/render/project/src
python init_production_db.py
```

**Method 2: Direct SQL**
```bash
psql $DATABASE_URL -f backend/db/seed.sql
```

**Method 3: Fresh Start (deletes all data)**
1. Supabase Dashboard → SQL Editor
2. Run: `DROP SCHEMA public CASCADE; CREATE SCHEMA public;`
3. Trigger Render redeploy
4. Automatic initialization will run on empty database
